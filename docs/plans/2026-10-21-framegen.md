# FrameGen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows video player that streams local files and YouTube and interpolates frames in real time with RIFE (TensorRT) up to 144fps, without stutter, crashes or broken seeking.

**Architecture:** The app is **mpv itself**, plus config and scripts:
- **uosc** (a third-party mpv UI script) gives the window its controls: open file, paste URL (Ctrl+V), YouTube quality menu.
- Our Lua script adds the FPS menu, auto performance mode, the failure fallback and the debug overlay.
- Our VapourSynth script (loaded through mpv's `vapoursynth` filter) runs RIFE through **vs-mlrt** (`vsmlrt.RIFE`, TensorRT backend). It holds frames across anime duplicates and scene cuts.
- A PowerShell launcher restarts mpv without interpolation if it ever crashes.
- An Inno Setup installer bundles everything.

No Python GUI and no custom player code.

**Tech Stack:** mpv ≥ 0.39 (shinchiro Windows build, has VapourSynth + `mp.input`), VapourSynth R70+ portable, vs-mlrt (TensorRT build + RIFE ONNX models), uosc 5.x, yt-dlp, Lua 5.1-compatible code (mpv's LuaJIT), Python 3.12 (VapourSynth's), PowerShell 5, Inno Setup 6.

**Spec:** `docs/specs/2026-10-21-framegen-design.md`

## Global Constraints

- Target hardware: RTX 4050 Laptop, 6 GB VRAM, 144Hz panel. FPS is capped at the display refresh rate (fallback cap 144).
- FPS choices: multipliers **1.5×, 2×, 2.5×, 3×**; fixed **60, 90, 120, 144**; custom value. Only targets above the source fps and at most the cap are offered.
- Step-down order: lighter RIFE settings → lower target fps → interpolation off with a notice. Auto mode **never changes stream quality mid-play**.
- Anime: hold duplicate drawings and never interpolate across scene cuts (on by default).
- Any interpolation failure → interpolation off, playback continues, notice shown.
- Stream, never download: yt-dlp via mpv's ytdl_hook.
- HDR: no tone-mapping in the filter. RIFE runs on the PQ/HLG-encoded values and the output keeps the source's colour tags, so mpv tone-maps for display as it normally does. *(This replaces the spec's "tone-map to SDR before RIFE": less code, same or better result.)*
- Lua modules other than `main.lua` must not touch `mp`, so they can be tested with plain `lua`.
- Commits: no AI/Claude attribution lines (user's global rule).

## Review Focus

1. **Seek latency:** mpv reloads the `.vpy` on every seek, so the TensorRT engine is deserialized again each time. Expectation: playback resumes within ~1s after a seek. Pinned by the Windows acceptance checklist (Task 6), measured as `seek ms` in the debug overlay.
2. **Unknown/broken `container_fps`** (0, NaN, VFR web streams). Expected: snap to a sane fraction, or use 30000/1001 when it's unknown. Pinned by `test_snap_fps` (Task 1) and `test_source_fps_fallback` (Task 3).
3. **Custom fps input that's garbage, below the source fps or above the cap.** Expected: rejected with a message, nothing changes. Pinned by `test_resolve_custom` (Task 1).
4. **Auto mode oscillating** up and down forever. Expected: a level that fails after stepping up is blocked for the rest of the file. Pinned by `test_blocks_after_failed_up` (Task 2).
5. **First run, before the TensorRT engines exist** (building takes minutes). Expected: video plays normally without interpolation and shows a "preparing" notice, never a frozen window. Pinned by `test_engines_missing_plays_plain` (Task 4, scripted with stub `mp`).


`ladder.json` (exact contents, tunable later):
```json
[
  {"label": "RIFE 4.26 full",   "model": 426,  "scale": 1.0},
  {"label": "RIFE 4.25 lite",   "model": 4251, "scale": 1.0},
  {"label": "RIFE 4.6 half",    "model": 46,   "scale": 0.5},
  {"label": "RIFE 4.6 quarter", "model": 46,   "scale": 0.25}
]
```
(vs-mlrt only allows `scale != 1.0` on models below 4.7, which is why the lower rungs use 4.6. The `model` values are `vsmlrt.RIFEModel` enum values.)

### Task 2: Auto performance state machine (`auto.lua`)

**Files:** Create `portable_config/scripts/framegen/auto.lua`, `tests/test_auto.lua`

**Interfaces — Produces:**
- `auto.fps_steps(target_num, target_den, src_num, src_den) -> list of {num,den}`, descending: target, then 60 if src < 60 < target, then 2×src if 2×src < target. Duplicates removed.
- `auto.levels(rife_count: int, fps_steps) -> list`: the RIFE levels `{rife=i, fps=1}` for i=1..R, then `{rife=R, fps=j}` for j=2..#fps_steps, then `{off=true}`.
- `auto.new(levels, now) -> state` (`level=1`, `warm_until=now+WARMUP`)
- `auto.tick(state, s, now) -> action` where `s = {drops=int, delayed=int, vf_fps=number, target=number}` (drops/delayed are cumulative mpv counters) and `action` is `"down"|"up"|nil`. On `"down"`/`"up"` it updates `state.level` and resets the warm-up.
- Constants: `WARMUP=3`, `BAD_TICKS=3`, `STABLE_UP=30`, `FAIL_WINDOW=10`.

- [ ] Step 1: Write `tests/test_auto.lua`:
  - `test_levels`: R=4 with 3 fps steps gives 4+2+1 = 7 levels, and the last is `off`.
  - `test_ignores_warmup`: bad samples during the first 3s do nothing.
  - `test_steps_down_after_3_bad`: a tick is bad when the drops delta > 0, the delayed delta > 2, or `vf_fps < 0.95*target`. Three consecutive bad ticks → `"down"`. Two bad, one good, two bad → nil.
  - `test_steps_up_after_stable`: 30s of good ticks at level 2 → `"up"` to level 1.
  - `test_blocks_after_failed_up`: up to level 1, then `"down"` within 10s → level 1 is blocked, and no further `"up"` happens however long it stays stable.
  - `test_off_is_terminal`: at the `off` level, no tick ever returns an action.

- [ ] Step 3: Implement `auto.lua` (pure, no `mp`). The state stores the previous counters for the deltas.

### Task 3: VapourSynth RIFE filter (`fg_vs.py`, `rife.vpy`, `ladder.json`, `build_engines.py`)

**Files:** Create `portable_config/vs/ladder.json` (contents above), `portable_config/vs/fg_vs.py`, `portable_config/vs/rife.vpy`, `portable_config/vs/build_engines.py`, `tests/test_fg_vs.py`

**Interfaces:**
- Consumes: `user_data` JSON from Lua: `{"num":int,"den":int,"level":int,"anime":bool,"engines":str}` (`level` is a 1-based index into ladder.json).
- Produces (pure, importable without vapoursynth):
  - `parse_params(user_data: str) -> dict`. Raises `ValueError` on missing or invalid keys, or on a `level` outside ladder.json.
  - `source_fps(container_fps: float) -> Fraction` (same snapping as `fps.snap`; 30000/1001 when unknown)
  - `source_pos(i: int, mult: Fraction) -> (n: int, frac: Fraction)` with `t = i / mult`
  - `should_hold(frac: Fraction, scene_next: bool, diff: float, anime: bool) -> bool`: True when `frac == 0`, or `scene_next`, or `anime and diff < DUP_THRESHOLD` (`DUP_THRESHOLD = 0.0015`, luma PlaneStatsDiff)
  - `backend(engines: str) -> vsmlrt.Backend.TRT`: `fp16=True, static_shape=False, min_shapes=(64,64), opt_shapes=(1920,1088), max_shapes=(3840,2176), engine_folder=engines`
  - `build(video_in, container_fps, params) -> vs.VideoNode` (VapourSynth only)

  - `test_should_hold`: frac 0 → True; scene cut → True; anime with diff 0.001 → True; non-anime with diff 0.001 → False; normal motion → False.
  - `test_source_fps_fallback`: 23.976 → 24000/1001; 0, NaN → 30000/1001.
  - `test_parse_params`: valid JSON round-trips; `level` 0 or 5, missing `num`, non-JSON → `ValueError`.
- [ ] Step 2: Run `tests/run.sh`. Expected: FAIL.
- [ ] Step 3: Implement the pure functions in `fg_vs.py`. Import `vapoursynth`/`vsmlrt` lazily inside `backend`/`build`, so the tests run on macOS.
- [ ] Step 4: Run. Expected: PASS.
- [ ] Step 5: Implement `build` with this chain:
  1. Trim `video_in` to a sane length (as the mpv docs advise).
  2. `AssumeFPS` to `source_fps`.
  3. `resize.Bicubic` to RGBH, using the source matrix and keeping transfer/primaries as they are (no tone-map).
  4. `rife = vsmlrt.RIFE(rgb, multi=mult, scale=..., model=RIFEModel(m), backend=backend(...), video_player=True)`.
  5. A detection clip: a tiny grey 1/8-size downscale with `misc.SCDetect(threshold=0.12)` and `std.PlaneStats(d, d[1:])`.
  6. A source-on-output-timeline clip: `std.FrameEval` returning `rgb[n]`.
  7. `std.FrameEval` with `prop_src=` the detection clip mapped to the output timeline; each output frame picks the source-timeline clip when `should_hold`, else `rife`. VapourSynth is lazy, so held frames cost no GPU time.
  8. Convert back to YUV420P10 with the source matrix, then `AssumeFPS(out num/den)`. This sets the `_DurationNum/_DurationDen` that mpv requires.

  `rife.vpy` is exactly:
  ```python
  import fg_vs
  fg_vs.build(video_in, container_fps, fg_vs.parse_params(user_data)).set_output()
  ```
  (`fg_vs` has to be importable, so `rife.vpy` inserts its own directory on `sys.path` before importing it.)
- [ ] Step 6: `build_engines.py <engines_dir>`: for each ladder level, push a 1920×1080 RGBH `BlankClip` through `vsmlrt.RIFE` with the same backend, and request one frame so vs-mlrt builds and caches the engine. Print `level i/N` for progress. On success, write `<engines_dir>/READY` containing the ladder.json hash.

### Task 4: mpv wiring (`main.lua`, configs)

**Files:** Create `portable_config/scripts/framegen/main.lua`, `portable_config/mpv.conf`, `input.conf`, `script-opts/framegen.conf`, `script-opts/uosc.conf`, `tests/test_main.lua`

**Interfaces — Consumes:** `fps.*`, `auto.*`, `overlay.*`, plus `user_data` keys from Task 3.

What `main.lua` does:
- **State:** `enabled` (default yes), `choice` (default `"x2"`), `src {num,den}`, `target {num,den}`, `auto_state`, `blocked_reason`.
- **`apply()`:** builds the user_data JSON and runs `vf set vapoursynth=file=~~/vs/rife.vpy:buffered-frames=8:concurrent-frames=4:user-data=%<len>%<json>` (mpv's `%len%` quoting), or `vf clr` when disabled/off. It runs on `file-loaded`, on an fps change and on an auto level change. It's skipped when the target ≤ source.
- **Engines:** if `<engines>/READY` is missing, it plays plain, shows `"Preparing RIFE (first run, several minutes)…"`, and starts `build_engines.py` via async `subprocess` using the bundled python. When that finishes, it calls `apply()`.
- **Failure:** `mp.enable_messages("error")`. A log line from `vf`/`vapoursynth`, or a Python traceback, while the filter is active → `enabled=false`, `vf clr`, and an OSD notice `"Interpolation turned off: <first error line>"` for 6s. Playback continues.
- **Auto:** a 1s periodic timer feeds `auto.tick` with `frame-drop-count`, `vo-delayed-frame-count`, `estimated-vf-fps` and the target fps. On `"down"`/`"up"` it calls `apply()` with the new level, and on reaching `off` it shows `"Too heavy for real-time: playing original fps"`.
- **FPS menu:** `script-binding framegen/fps-menu` opens a uosc menu via `script-message-to uosc open-menu <json>`, built from `fps.options`, plus a "Custom…" entry (`mp.input.get`, validated by `fps.resolve`) and an "Interpolation on/off" entry.
- **Crash resume:** writes `{path, pos}` to `~~/state/last.json` every 5s and on shutdown.
- **Seek timing:** measures the time from `seek` to the next `playback-restart` (`seek ms` for the overlay).
- **Debug overlay:** `D` toggles it (input.conf: `D script-binding framegen/debug`).

Configs:
- `mpv.conf`: `vo=gpu-next`, `hwdec=auto-copy`, `video-sync=display-resample`, `interpolation=no`, `framedrop=vo`, `ytdl-format=bestvideo[height<=?1440]+bestaudio/best` (auto quality: picked once at load, `# ponytail: fixed 1440p cap, learn from auto results if needed`), `script-opts-append=ytdl_hook-ytdl_path=yt-dlp.exe`, `osc=no`, `border=yes`, `keep-open=yes`, `save-position-on-quit=no`.
- `uosc.conf`: adds an FPS button to `controls` that runs `script-binding framegen/fps-menu`, and sets `stream_quality_options=2160,1440,1080,720,480`.

- [ ] Step 1: `tests/test_main.lua` stubs `mp`, `mp.utils`, `mp.msg` and `mp.input` as recording tables, then loads `main.lua`:
  - `test_engines_missing_plays_plain`: with no READY file, `file-loaded` issues no `vf set`, starts one subprocess and shows the OSD "Preparing" text.
  - `test_apply_quotes_user_data`: the issued vf string has `user-data=%N%` and N equals the byte length of the JSON.
  - `test_failure_disables`: a vapoursynth error log line → `vf clr` and the notice.

### Task 5: Debug overlay (`overlay.lua`)

**Files:** Create `portable_config/scripts/framegen/overlay.lua`, `tests/test_overlay.lua`. `main.lua` draws it through `mp.create_osd_overlay("ass-events")` every 250ms while debug is on. When it's off, no timer runs.

**Interfaces — Produces:**
- `overlay.graph(samples: {number}, x, y, w, h, vmax) -> string`: an ASS `{\p1}` drawing path (`m x0 y0 l …`). It returns `""` for fewer than 2 samples, and values are clamped to `[0, vmax]`.
- `overlay.render(st) -> string`: the ASS events. `st` holds `src_res, src_fps, target_fps, real_fps, display_fps, level_label, backend, auto_level, auto_total, drops, delayed, vram_mb, seek_ms, hist {real_fps={}, frame_ms={}, drops={}, vram={}}`.

What the overlay shows:
- Text rows: `src 1920×1080 @ 23.976 → target 60.000 | real 59.8 | display 144`, `RIFE 4.26 full · TRT · level 1/7`, `dropped 0 · late 0 · VRAM 2310 MB · seek 420 ms`.
- Three small graphs (120 samples each): real fps (vmax = target×1.2), filter frame time in ms (`1000/estimated-vf-fps`, which stands in for RIFE inference time), and VRAM.
- Layout: top-left, font size 14, background alpha 60%.
- VRAM is polled every 2s via async `nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits`, only while debug is on.

  - one sample → `""`

  - `render` contains `"→ target 60.000"` and `"level 1/7"`

### Task 6: Packaging (`build.ps1`, `launch.ps1`, `installer.iss`) + Windows acceptance

**Files:** Create `packaging/build.ps1`, `packaging/launch.ps1`, `packaging/installer.iss`, `README.md`

- [ ] Step 1: `build.ps1` (runs on Windows) downloads these pinned releases into `build/app/` (version variables at the top of the script):
  - mpv shinchiro x86_64-v3
  - VapourSynth portable plus Python 3.12 embeddable, into `vs-runtime/`
  - vs-mlrt TensorRT build plus the RIFE models listed in ladder.json, into `vs-runtime/vs-plugins` / models
  - uosc, into `portable_config/scripts/`

  It then copies our `portable_config/` and runs `iscc packaging/installer.iss`. It fails loudly on any checksum or download error.
- [ ] Step 2: `launch.ps1`:
  1. Prepends `vs-runtime` to `PATH` and runs `mpv.exe --config-dir=portable_config $args`.
  2. If the exit code isn't 0–4 (a crash), it reads `state/last.json` and relaunches with `--start=<pos> --script-opts=framegen-enabled=no <path>`, and shows a toast/OSD `"Recovered from a crash, interpolation off"`. Relaunch happens at most twice per session.
  3. Once a week, in the background, it runs `yt-dlp.exe -U`.
- [ ] Step 3: `installer.iss` installs to `{localappdata}\FrameGen`, with a Start-menu and desktop shortcut to `powershell -WindowStyle Hidden -ExecutionPolicy Bypass -File launch.ps1`. No file associations.
